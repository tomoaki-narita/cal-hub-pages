複数のカレンダー連携、対応する勤務表PDFの取込み、データの保存先について説明します。

This policy explains calendar integrations, work schedule PDF import, and where app data is stored.

最終更新日: 2026年10月16日

Last updated: October 16, 2026

Calendar Hub（Cal Hub）は、Appleカレンダー、Googleカレンダー、Notionデータベースを切り替えて予定を管理するアプリです。対応する勤務表PDFから予定を取り込んで選択中の登録先へ登録する機能もあります。このポリシーでは、アプリが扱う情報と保存先を説明します。

アプリが扱う情報

01 / 端末内

勤務予定とアプリの設定

ユーザーがスキャンするPDF、PDFから読み取った勤務予定、イベント設定、表示設定、登録先の設定を扱います。

02 / iCLOUD

同期される情報

新規インストールではiCloud同期はオフです。有効にした場合、アプリ設定と保存済みPDFをユーザー自身のiCloud領域に保存します。

03 / 外部サービス

カレンダーとデータベースの情報

Appleカレンダー、Googleカレンダー、Notionの情報は、ユーザーが該当サービスへの接続や取得・登録を行う際に扱います。

カレンダー連携

ユーザーが連携するサービスと登録先を選ぶと、アプリは手動操作に応じて情報を各サービスへ送受信します。また、設定された間隔でのバックグラウンド取得やウィジェット更新のために、カレンダー情報を自動取得する場合があります。予定の登録・編集・削除は、ユーザーがアプリで実行した場合に行われます。

Google Calendar API: GoogleログインはmacOSではGoogle Sign-In SDK、iOSではOAuth PKCEを使用します。macOSのGoogle認証では、認証画面にGoogleアカウントの基本情報（氏名、メールアドレス、プロフィール画像など）の共有が表示される場合があります。アクセストークンとリフレッシュトークンは端末のKeychainに保存します。OAuth権限は、Googleアカウントで利用できるカレンダー一覧の参照と、そのアカウントがアクセスできるGoogleカレンダー全体の予定の表示・編集を許可します。この権限自体は特定のカレンダーIDには限定されません。Cal Hubはカレンダー一覧からユーザーが選んだ登録先を表示し、通常は選択中のカレンダーの予定を取得・表示します。予定の登録・編集・削除も、そのカレンダーでユーザーが依頼した操作に限ります。Googleの祝日表示を有効にした場合は、表示用に祝日カレンダーの予定も取得します。

Googleユーザーデータは、ユーザーが要求したカレンダー機能の提供にのみ使用し、広告目的には使用しません。Google APIから受け取ったデータの利用は、Google API Services User Data Policy（Limited Use要件を含む）に従います。

NotionはOAuthで接続し、Notionの承認画面で共有を許可したデータベースからアプリで登録先を選択します。認証コードの交換とリフレッシュトークンの更新はCloudflare Workerを経由します。WorkerはOAuth処理に必要なNotionのクライアントシークレットをWorker Secretとして保管し、認証情報をNotion APIへ送信します。初回接続時にNotionから返されたトークン応答は端末へ一度だけ渡すため一時保存します。チケットは一度しか使えず、10分経過後は取り出せません。期限後のクリーンアップで保存データを削除します。Notionのアクセストークン、リフレッシュトークン、ワークスペース名・IDは端末のKeychainに保存します。Notionのデータベースや予定の内容は端末とNotion APIの間で送受信し、Workerには送信・保存しません。Workerのコードはトークンや予定内容をログに記録しません。アプリで接続を解除すると端末のトークンを削除しますが、Notion側の許可も解除するにはNotionの設定でCalendar Hubとの接続を削除してください。

Notion OAuthの中継にCloudflare Workerを使用します。Cloudflareのインフラでは、通信の処理に必要な技術情報（IPアドレスなど）が扱われる場合があります。詳しくはCloudflareのプライバシーポリシーをご確認ください。

保存と共有

スキャンしたPDF、イベント設定、接続先設定、カレンダー表示用のキャッシュは端末に保存されます。iCloud同期は新規インストール時にオフで、ユーザーが有効にするとアプリ設定と保存済みPDFをユーザー自身のiCloud領域へ保存します。同期をオフにしても既存のiCloudデータは残ります。一般設定の「iCloud同期データを削除」から同期をオフにして、iCloud上の設定・保存済みPDF・同期レコードを削除できます。この操作は端末内の設定やPDFを削除しません。削除が完了しなかった場合はアプリに結果が表示されます。カレンダーイベントやOAuthトークンはiCloud同期しません。ウィジェット表示用のイベントスナップショットはアプリとウィジェットが共有する端末内領域に保存され、iPhoneでは表示用データをペアリング済みApple Watchへ送信してWatch側にも保存します。Notion OAuthの認証情報はCloudflare Workerを通過しますが、予定・データベース内容はWorkerへ送信・保存しません。

広告と外部サービス

このアプリは、ユーザーが選択したPDFやカレンダーの内容を広告目的で利用しません。各カレンダーサービスの利用や、各サービス上でのデータ保存には、それぞれのサービスのポリシーが適用されます。

免責事項

Calendar Hub (Cal Hub) lets users switch between Apple Calendar, Google Calendar, and Notion databases to manage events. It also supports importing events from compatible work schedule PDFs into the selected destination. This policy explains the information handled by the app and where it is stored.

Information handled by the app

01 / ON DEVICE

Schedules and app settings

The app handles PDFs selected for scanning, schedule information read from those PDFs, event definitions, display preferences, and calendar destination settings.

02 / ICLOUD

Data synced when enabled

iCloud sync is off by default for new installations. When enabled, app settings and saved PDFs are stored in the user's own iCloud account.

03 / EXTERNAL SERVICES

Calendar and database information

Information from Apple Calendar, Google Calendar, and Notion is handled when the user connects to a service or fetches or registers information.

Calendar integrations

When a user selects a service and destination, the app exchanges information with that service in response to user actions. Calendar information may also be fetched automatically at the configured background interval or to update widgets. Event creation, editing, and deletion occur when the user requests them in the app.

Google Calendar API: Google sign-in uses the Google Sign-In SDK on macOS and OAuth with PKCE on iOS. The macOS Google consent screen may ask to share basic Google Account information such as name, email address, and profile photo. Access and refresh tokens are stored in the device's Keychain. The OAuth grant allows Calendar Hub to list calendars available to the Google Account and to view and edit events across the calendars that account can access; it is not limited to one calendar ID. Calendar Hub lists writable calendars so the user can choose a destination and normally fetches and displays events from the currently selected calendar. It creates, edits, or deletes events there only when the user requests those actions. If Google holiday display is enabled, events from the holiday calendar are also fetched for display.

Google user data is used only to provide calendar features requested by the user and is not used for advertising. The app's use of data received from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements.

Notion connects through OAuth, and users choose a destination from databases they allowed on Notion's authorization screen. Authorization-code exchange and refresh-token renewal pass through a Cloudflare Worker. The Worker stores the Notion client secret as a Worker Secret and sends authentication details to Notion's API. During initial connection, the token response is temporarily stored for one-time delivery. The ticket can be used once; after 10 minutes it can no longer be redeemed, and cleanup deletes the stored response. Notion access and refresh tokens and the workspace name and ID are stored in the device's Keychain. Database and event content is sent between the device and Notion API, not to or stored by the Worker. The Worker code does not log tokens or event content. Disconnecting in the app deletes tokens on the device; to revoke Notion-side access too, remove Calendar Hub from Notion settings.

Cloudflare Worker is used to relay Notion OAuth requests. Cloudflare's infrastructure may process technical information needed for network requests, such as IP addresses. See Cloudflare's Privacy Policy for details.

Storage and sharing

Scanned PDFs, event definitions, connection settings, and calendar display caches are stored on the device. iCloud sync is off for new installations. If enabled, app settings and saved PDFs are stored in the user's private iCloud account. Turning sync off leaves existing iCloud data in place. General settings includes an option to turn sync off and delete synced settings, saved PDFs, and CloudKit records. It leaves local settings and PDFs on this device intact and reports if deletion could not be completed. Calendar events and OAuth tokens are not synced through iCloud. Widget event snapshots are stored in a local area shared with the widget; on iPhone, display data is sent to a paired Apple Watch and stored on the Watch. Notion OAuth credentials pass through a Cloudflare Worker, but event and database content is not sent to or stored by the Worker.

Advertising and external services

The app does not use PDFs or calendar contents selected by the user for advertising. Each calendar service's policies also apply to its services and the information stored there.
